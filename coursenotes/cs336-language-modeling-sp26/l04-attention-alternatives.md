# 第 4 讲 · 注意力替代方案与混合专家

> **Stanford CS336 语言模型从零构建 · L04** ｜ 讲者 Stanford Online ｜ 86 分钟 ｜ [原视频](https://www.youtube.com/watch?v=cKSwj_qZ8Jg)

## 核心结论

本讲讨论两类“在标准 Transformer 之上”的进阶架构改造：一是替换注意力块，用线性时间注意力及其混合变体把长上下文的成本从二次降为近似线性；二是替换 MLP 块，用混合专家（MoE）在不增加前向 FLOPs 的前提下大幅增加参数量。线性时间注意力的关键起点是矩阵乘法的结合律——去掉 softmax 后重排括号，就能把对序列长度的二次依赖转移到隐藏维度上，并由此得到“训练用稠密矩阵乘、推理用 RNN 递推”的对偶形式。目前所有在规模上验证过的方案都是混合式的：少量全注意力层配大量线性/门控递推层，且混合比例过高会带来可测量的长上下文性能退化。MoE 的核心是 token 级 top-k 路由加负载均衡辅助损失：路由本身不可微、训练时也看不到未被选中的专家，但一套简单启发式规则足以让它稳定训练；代价是复杂的专家并行与通信开销。

## 课程定位：两条改造主线 [00:05 - 01:32]

![CS336 课程第四讲标题页：注意力替代方案与专家混合模型](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0003_00-00-26.jpg)

上一讲讨论的是基础 Transformer 以及如何微调各个部件得到现代语言模型；本讲讨论两个更“进阶”的方向：

1. **注意力替代方案（attention alternatives）**：通过架构改动支持更长的上下文，使计算量对序列长度大体呈线性而非二次依赖。
2. **混合专家（mixture of experts, MoE）**：改造 MLP 部分，在给定计算量下获得更好的硬件利用率，也就是用更多参数换同样的 FLOPs。

---

## 长上下文的成本结构：注意力为何成为瓶颈 [01:32 - 02:49]

各家 LM 厂商都在竞赛式地扩大上下文窗口（幻灯片横轴为时间、纵轴为上下文长度，取对数刻度），以支撑更复杂的工作负载（更多知识、agent 类任务）。

成本结构随之改变：前馈部分的计算量随序列长度**线性**增长，而注意力是全部位置之间的 all-to-all 连接，呈**二次**增长。因此在较小序列长度、大模型时代，FFN 是主导成本；序列变长后，注意力迅速反超，成为主要开销。

## 基础工具箱：局部/全局混合与系统常数 [02:49 - 05:08]

![基础工具箱：局部+全局注意力组合示意图与各注意力实现在不同序列长度下的速度对比柱状图](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0004_00-02-53.jpg)

在走向线性时间之前，有两类“常规”手段：

- **架构混合**：把局部注意力与全局注意力组合起来。例如每 8 层只做一次全局注意力，其余层都用代价很低的局部注意力，就能有效控制成本。
- **系统工程**：常数因子极其重要。FlashAttention 并没有改变二次复杂度，只是把注意力运算重排成对系统更友好的形式，以减少显存搬运开销，却带来了成倍的实测加速；在朴素实现已经放不进显存的序列长度上，它仍能跑（虽然会变慢）。

但如果要处理 500 万到 1000 万 token，这些技巧就不够了，需要更根本的线性时间方案。

## 线性注意力：结合律带来的复杂度重排 [05:45 - 08:04]

![线性注意力推导：利用矩阵乘法结合律将复杂度从二次降为线性](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0005_00-05-45.jpg)

注意力写作

$$\mathrm{Attn}(Q,K,V)=\rho(QK^\top)V,\quad Q,K\in\mathbb{R}^{n\times d_k},\ V\in\mathbb{R}^{n\times d_v}$$

二次复杂度来自 $QK^\top$（$n^2d_k$）。**关键一步是先把 softmax（$\rho$）去掉**，令其为恒等映射，然后利用结合律换括号：

$$(QK^\top)V = Q(K^\top V)$$

复杂度从 $n^2d_k+n^2d_v$ 变为 $2nd_vd_k$：依赖对象从“序列长度 $n$（可达百万量级）”变成“隐藏维度（通常几千到几万）”。讲师强调这一步“看起来很傻，但出乎意料地重要”。

注意：这一步是**有损的**——从 softmax 注意力到线性注意力并不等价；而后面从线性形式到递推形式的转换则是**精确等价**的。

## 线性注意力的 RNN 对偶：训练并行、推理串行 [08:04 - 09:52]

![线性注意力的循环形式推导，展示(QK^T)V=Q(K^TV)重排及RNN式状态更新公式](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0006_00-08-38.jpg)

把 $Q(K^\top V)$ 按时间步展开，就得到一个递推形式：

$$S_t = S_{t-1} + k_t v_t^\top,\qquad y_t = q_t^\top S_t$$

即用固定大小的状态 $S$ 增量累加 $kv^\top$，再用 $q$ 读出。稠密形式与 RNN 形式等价，于是同时获得两边的好处：

- **训练**：用稠密矩阵乘，可并行；
- **推理**：用递推形式，状态大小固定，逐 token 推进。

问答补充：有同学问两种形式是否只是“近似等价、略有性能损失”。讲师澄清，损失只发生在第一步去掉 softmax 时；线性形式与循环形式之间的等价是精确的。

## 生产中的线性注意力混合：MiniMax M1 与 Mamba-2 [09:53 - 14:15]

![MiniMax M1模型性能对比柱状图、FLOPs随生成长度增长曲线及7:1混合注意力架构图](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0007_00-10-04.jpg)

**MiniMax M1**（大规模、高性能的中文开源模型）采用 **7:1 混合**：7 层线性注意力 + 1 层完整 softmax 注意力，性能与同期强模型可比，对上下文长度的依赖大幅变缓（不是完全线性，因为仍有 softmax 层）。这说明最朴素的线性注意力在规模上就可用——**前提是保留少量全连接（二次）层**。讲师强调：迄今没有人真正在规模上验证过“纯线性时间注意力”，接下来讲的全部是混合方案。

![从线性注意力推广到Mamba-2的门控公式及串行/并行Mamba块结构图](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0008_00-11-31.jpg)

**Mamba-2**：从线性注意力的递推形式出发，加一个门控 $\gamma_t$：

$$S_t=\gamma_t S_{t-1}+k_tv_t^\top,\qquad y_t=q_t^\top S_t+v_t^\top D,\qquad \gamma_t=f(x_t)$$

$\gamma_t$ **只依赖当前输入、不依赖状态**，因此仍保持“稠密矩阵乘 / 递推”两种等价写法，训练效率与推理效率兼得。其中 $v_t^\top D$ 是让当前步的 value 直接透传到输出的一项（类似残差），$D$ 是控制透传量的门控；它不是状态更新的核心，加上只是为了完整呈现 Mamba-2 的真实形式。

Nemotron 3 就是把 Mamba-2 当作轻量层、与全 softmax 注意力层交替堆叠的例子，在较大上下文长度下有不错的吞吐，性能也可接受（属于开源的小型前沿模型）。

## Gated DeltaNet：加门控与“擦除” [14:15 - 18:49]

![Gated Delta Net 与 Mamba-2 的状态更新公式对比及门控机制说明](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0009_00-14-23.jpg)

**经验法则**：只要递推中所有门控都只依赖输入、不依赖状态，就仍保有“并行训练 / 串行推理”的对偶性。

**Gated DeltaNet** 在 Mamba-2 基础上再加一个门 $\beta_t$：

$$S_t=\gamma_t\left(I-\beta_t k_t k_t^\top\right)S_{t-1}+\beta_t k_t v_t^\top,\qquad y_t=q_t^\top S_t$$

- $\beta_t$ 可理解为“**无输入操作**门”：$\beta_t=0$ 表示不把当前信息写入状态，非常像 LSTM 的输入门；$\gamma_t$ 则对应遗忘门。
- $(I-\beta_t k_t k_t^\top)$ 是一个**投影/擦除**项：写入当前 key 方向的新信息时，同时把状态中沿该 key 方向的旧信息投影掉（这里没有做归一化，只是直觉）。这个更新式在 fast weight programming、test-time training 等完全不同的设计路径中被独立重新发现过。

![Qwen 3.5 / Qwen Next 的混合架构图、基准测试得分及解码吞吐量随上下文长度变化曲线](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0010_00-18-42.jpg)

Qwen 3.5 / Qwen Next 采用 **3:1 的 Gated DeltaNet : Attention 混合**，是当前最好的开源模型之一；随着上下文变长，其解码吞吐显著高于上一代，而性能相对稠密/全注意力基线几乎没有损失。

## 混合比例的经验研究 [19:01 - 20:41]

![混合线性注意力机制的系统性分析幻灯片，包含模型更新规则表格与不同混合比例下的性能折线图](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0011_00-20-09.jpg)

目前关于混合架构的**受控研究并不多**，相对系统的一份来自 ByteDance Seed 与 UC Santa Cruz：把 Mamba-2、Gated DeltaNet 等作为“非全注意力层”，扫描其比例。

- 横轴向右 = 非全注意力（递推）层比例上升，纵轴为长上下文性能；虚线为全注意力性能。
- 低混合比例下（较好的几种架构）性能几乎无损；超过某个点后退化明显；到纯 RNN 时所有架构都有可见退化。
- QA 类评测也呈同样趋势（单 key 检索这类任务可能被这些架构专门优化过，参考价值较弱）。

## 稀疏注意力：DeepSeek DSA 的轻量索引器 + top-k [22:50 - 29:20]

![DSA（DeepSeek稀疏注意力）原型结构说明，包含闪电索引器公式与细粒度token选择机制](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0012_00-23-01.jpg)

另一条完全不同的路线：**不追求线性时间**，而是先用一个轻量 indexer 选出少量 token，再只在这个子集上做完整注意力。

$$I_{t,s}=\sum_{j=1}^{H^I} w^I_{t,j}\cdot\mathrm{ReLU}\left(q^I_{t,j}\cdot k^I_s\right)$$

对每个位置按上述得分取 **top-k**，再对选中的 $c_s$ 集合做常规注意力：

$$u_t=\mathrm{Attn}\left(h_t,\{c_s\mid I_{t,s}\in\mathrm{Top\text{-}k}(I_{t,:})\}\right)$$

要点与问答：

- indexer 本身**仍是二次的**（必须看所有 token 才能选出子集），但可以做得极轻：更低精度、更低维（对 Q/K 额外投影）、更小的权重矩阵。第二阶段虽然也是二次，但只在受控的 $k$ 上做——“贵，但规模小”，常数因子才是关键。
- **不需要在预训练时就引入**：先正常预训练短上下文模型，在**长上下文扩展阶段**再插入 indexer 并训练模型适应。常见流程是：短上下文预训练 → 长上下文扩展 → 后训练。能这样“bolt-on”一个看似可怕的 top-k 不可微结构，本身是有点反直觉的。
- $k$ 的取值通常与短上下文长度同量级，从而把成本上界固定住。
- 稀疏选择的思路也出现在 MoE 里，是后半讲的核心伏笔。

![DSA在DeepSeek-V3.2与GLM5上的多基准性能对比及推理成本曲线](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0013_00-25-54.jpg)

DeepSeek-V3.2 使用 DSA 后与同期前沿模型性能相当，prefill 与 decode 的成本曲线都明显优于上一代；GLM 5 也采用 DSA，并给出了较细的消融：完整 DSA 训练相对全注意力性能损失很小，即使在较难的长上下文检索任务上也是如此（这类任务对 RNN 式架构通常不友好）。

其他问答：

- **去掉 softmax 是否带来训练稳定性问题？** 讲师没有见过相关记录，反而认为 softmax 才是稳定性问题的主要来源，去掉它可能改善稳定性。
- **FP4 注意力是否可行？** 可能，但 softmax 对精度损失（下溢/上溢）很敏感；“低精度做选择、全精度做计算”正是 indexer 的一个动机。
- **状态空间模型相对 Transformer 的劣势？** 表达能力：有限状态必须把整个上下文压缩进去，状态越小越难；过去 attention 相对 LSTM 的优势之一是硬件效率（可并行训练），而线性注意力对偶把这个短板补上了，剩下的就是表达能力这一取舍。
- **对未来的预测？** 大概率是把各种有效配方都堆进去，外加用后训练让模型自己管理上下文（压缩、检索等），形成更高层的机制。

## MoE：把 FFN 换成稀疏专家 [34:22 - 39:42]

![MoE模型发展时间线与Mistral、DeepSeek、Llama 4等代表性模型介绍](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0015_00-34-25.jpg)

MoE 在概念上并不改变游戏规则，可以理解为“一个更高效的 MLP”：它只是替换 Transformer 里的 FFN。但值得学，原因有二：几乎所有大模型都在用；它的路由/选择原语在别处也反复出现（如 DSA 的 top-k）。

![稠密模型与稀疏MoE模型架构对比图，展示FFN层替换为多个专家网络及选择器](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0016_00-35-59.jpg)

基本构造：把一个大 FFN 换成 $N$ 个同样大的 FFN（专家）+ 一个选择器。每个 token 只走其中少数几个，于是**参数量是 $N$ 倍，而前向/反向的 FLOPs 仍只是一个 FFN 的量**。

![MoE模型流行原因的数据图表：相同FLOP下参数越多性能越好](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0017_00-37-25.jpg)

![MoE与Dense模型训练速度及性能对比图表，显示MoE训练速度提升7倍](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0018_00-38-51.jpg)

**为什么流行**：在总算力不变的前提下增加稀疏参数，模型普遍变好。

- Switch Transformer 的实验：固定激活参数量、增加专家数，语言建模 test loss 持续下降；固定训练算力、增加专家数同样更好。训练和推理都像是“免费收益”。
- OLMo 的开源 MoE 分析也观察到同样趋势：相对稠密模型训练更快（讲师提到约 2 倍量级），训练/验证 loss 与下游基准都更好。
- 以激活参数衡量，MoE 明显强于稠密模型；DeepSeek V2 及更早的 DeepSeek MoE 相比同期稠密模型，用少得多的激活参数取得了不逊甚至更好的 MMLU 表现。

![MoE Transformer编码器在多设备上的并行化架构图，展示All-to-All通信机制](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0019_00-40-18.jpg)

**额外好处：多一个并行轴**。每个专家天然是一个可切分的块，可以放到不同设备上，把激活路由过去（专家并行，expert parallel），为服务/训练优化提供新的自由度。

## 产业格局与早期证据 [39:42 - 47:23]

![Qwen等中国团队早期MoE模型与Dense模型在多项基准测试上的性能对比表格](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0020_00-41-44.jpg)

- MoE 的研究与训练大量发生在中国：Qwen、DeepSeek、MiniCPM 等较早训练并推广 MoE。Qwen1.5-MoE-A2.7B（14.3B 总参数、2.7B 激活）在当时优于许多 7B 稠密模型，这类早期验证说服了开源社区。

![DeepSeek关于MoE架构与稠密模型性能对比的实验数据表](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0022_00-44-30.jpg)

DeepSeek 长期在做扎实的架构与 LLM 科学研究，其早期 MoE 论文里有大量消融（稠密层 vs hash 路由 vs switch 路由等），是学习架构设计决策的好材料。

**为什么 MoE 普及得慢**：基础设施复杂（专家并行难以做到高利用率）、参数量大难以单机容纳、训练容易“炸”。MoE 并不是好对付的对象，只是现在有了较好的经验规则。

补充说明：也存在对**注意力块**做 MoE 的工作，但远不如替换 FFN 常见，也更难调稳，所以本讲只讨论 FFN 侧。

现场问答：

- **专家并行的通信瓶颈**：确实存在，本质是用通信换聚合 FLOPs 与显存节省，是否为净收益取决于网络拓扑。
- **路由粒度**：token 级，每个 token 独立选专家；路由器极其简单（一次矩阵乘），不存在“医学专家/法律专家”那种语义 specialization。

## 路由设计：token choice top-k 是共识 [47:23 - 58:00]

设计空间可沿三条轴变化：**路由函数**、**专家大小/数量**、**训练方法**。

**谁选谁**：

- token 选专家（token choice）vs 专家选 token（expert choice）vs 全局最优指派。
- OLMo 的对比显示 token choice 的验证 loss 更低、下游基准更高；expert choice 也能训，但 token choice 更容易调通，是当今所有主流模型的标准做法。

**具体路由函数**：

| 方案 | 说明 | 采用情况 |
|---|---|---|
| 内积路由 | 每个专家一个向量，取与输入内积最大的 top-k | 绝对主流：Switch Transformer、GShard、Grok、Mistral、DBRX、DeepSeek 等 |
| 哈希路由 | 直接对输入做哈希分派 | 论文里常见基线，确有收益（不如 top-k），但不用于部署 |
| RL / bandit 路由 | 把路由当策略学习（Bengio 2013 起） | 理论自然，但 RL 开销与随机性大，不常用 |
| 线性指派 | 计算所有 (token, expert) 配对得分，精确求最优指派 | 有小规模好结果，但太贵，未见规模应用 |

**top-k 路由的形式**：对输入 $u$ 计算各专家的得分 $s=\mathrm{softmax}(u^\top W)$，取 top-k 作为门控：

$$y=\sum_{i\in\mathrm{TopK}(s)} s_i\cdot \mathrm{FFN}_i(x)+x$$

门控的学习极其轻量——每个专家一个权重向量做内积，没有复杂结构。

**DeepSeek 的两个设计（现已成为标准）**：

- **细粒度专家**：把专家切得更小、数量更多；
- **共享专家（shared experts）**：一部分专家绕过路由器、对所有 token 始终生效，承担公共处理，让其余专家更专门化。

DeepSeek 的消融显示细粒度化与共享专家都带来明显收益（TriviaQA、Natural Questions 等）；OLMo 的受控研究认同“细粒度多专家有益”，但认为共享专家帮助不大——两家在此点上略有分歧。无论如何，DeepSeek V1 起的这套设计（细粒度 + 共享专家 + top-k + 辅助损失）已成为 MoE 的“标准模板”，地位类似稠密 Transformer 里的 Llama 设计。

问答：共享专家无法获得并行收益（每个激活都要经过它），可以复制共享专家以省通信、换显存。

## MoE 的训练难题：稀疏、不可微与负载均衡 [58:00 - 69:06]

难点在于：为了效率，训练时也**必须稀疏**（否则要付全部专家的 FLOPs）；但稀疏意味着 (1) 门控决策不可微，(2) 看不到未被选中的“反事实”专家。问题带有 bandit / RL 的色彩。

三条可能路线：

1. **RL 优化路由**（Clark 2020 等）：能工作，但梯度方差大、复杂度高，被后续更简单的方案胜过。
2. **随机扰动**：最早的 MoE 工作（Shazeer 等）在路由内积上加与输入尺度相关的噪声，再做 top-k + softmax——近似并列的专家会被随机选中，梯度随后强化有用的专家，起到探索与 tie-break 作用。Fedus 等 2022 还试过乘性扰动以“硬化”专家，但**后续 Google 的论文移除了它**，消融显示不做这些随机稳健化技巧反而更稳定、最终质量更好。
3. **启发式（实际采用）**：负载均衡辅助损失。

**为什么必须均衡**：普通梯度下降会形成“富者愈富”——被选中的专家获得更多梯度、权重更强、更常被选中，最终**专家坍缩/饥饿**，大量参数白费。

**Switch Transformer 的辅助损失**：设 $f_i$ 为分派到专家 $i$ 的 token 比例，$P_i$ 为路由器分配给该专家的概率质量，最小化

$$L_{\text{aux}}=\alpha N\sum_{i=1}^{N} f_i P_i$$

这个式子不易从第一原理推出，最好看它的梯度：对 $P_i$ 求导得到 $f_i$，即“越热门的专家，受到越强的负梯度压制”，且压制强度与其分派比例成正比。

**DeepSeek 的工程化扩展**：

- V1/V2：正常反传穿过专家（忽略不可微与探索问题）+ 逐专家均衡损失（同 Switch），**再加一个按设备（per-device）的均衡损失**——专家分布在不同机器上时，希望每台机器的利用率也均衡。逐专家损失若被完美满足，理论上也能带来设备均衡，但把逐专家损失调到“完全均匀”会损害训练动态，因此宁可额外加一项设备损失。
- V3：改用逐专家 bias 项 + 在线学习来均衡，减少辅助损失（aux-loss-free），但仍保留少量辅助损失以防极端失衡；目前还没有能完全去掉它们的方案。

**去掉负载均衡会怎样**（OLMo 消融）：训练/验证 loss 显著变差；更直观的是专家利用率图——没有均衡损失时几乎所有 token 都涌向两个专家，其余专家整个训练期间几乎不起作用。

**训练的整体图景**：一个含 top-k 非可微选择的复杂系统，只需加一个均衡损失，其余部分当作可正常反传即可稳定训练。有用的专家被正反馈强化，均衡损失把这种强化抵消掉，两种动态相互制衡。讲师指出，这套 “top-k 选择 + 辅助损失” 的模式也被用于 DSA、H-Net 等，未来很可能成为架构设计的常用配料。

## 系统层面：专家并行、通信与 dropless [69:06 - 76:35]

![MoE Transformer编码器在多设备上的并行化架构图，展示All-to-All通信机制](/coursenotes/cs336-language-modeling-sp26/l04-attention-alternatives/kf_0019_00-40-18.jpg)

- 数据并行受限于最大 batch size，模型并行受限于可切分点；**专家并行**提供新的并行轴，很多实现能利用 GPU 原生的稀疏矩阵乘。
- 单个 GPU 上多个小专家若拆成多次小矩阵乘会损失缓存复用；更好的做法是用**块对角/结构化稀疏**的矩阵乘，把“多专家 × 多输入”表达成硬件友好的大矩阵运算——这是 MoE 与硬件协同设计的一个契合点。
- **通信优化**（Nemotron 3 的例子）：专家并行的 All-to-All 需要把激活搬到对应设备，开销显著。可以把残差流先**下投影**成更低维向量再发送，从而省通信，同时不必永久缩小隐藏维度。共享专家不参与通信，无需此处理（可复制它来减少通信）。
- **随机性问题**：早期实现中，热门专家的 token 队列会积压，最终**静默丢弃** token（返回 0 当作正常），导致“其他用户命中同一专家就可能让你结果变差”这类诡异行为。现在 MegaBlocks 等 dropless 架构已基本解决。

---

## 稳定性与微调 [76:35 - 79:39]

- **路由里的 softmax 是新的稳定性风险点**。常见做法：路由器单独用 float32；加 **z-loss** 约束 softmax 的稳定性。OLMo 的消融显示 z-loss 能明显减少训练 loss 的尖峰。讲师提到早期 Google 的 MoE 工作就专门讨论过这些问题。
- **微调易过拟合**：MoE 参数量巨大，微调时 train/val gap 远大于稠密模型。常见缓解手段：只微调注意力层（近期 MoE 工作中很常见）、只微调非 MoE 的 FFN 层、或干脆用海量数据（“苦涩的教训”式做法，例如上百万条样本时几乎可以整体重训 MoE，泛化差距就不明显了）。

## Upcycling：从稠密模型“长”出 MoE [79:42 - 82:11]

做法：取一个已训练好的稠密模型，把每个 MLP 复制多份作为专家，路由器随机初始化，然后继续训练。由于输入分派的随机性，专家会逐渐分化专门化，最终得到一个 MoE。

- 早期论文显示，upcycle 后的模型比继续训练原稠密模型有更好的语言建模/准确率表现。
- 规模验证：MiniCPM 把 2.4B 模型 upcycle 到 13.4B；Qwen 把 1.8B 模型 upcycle 成 2.7B 激活的 Qwen-MoE，是较早的大规模成功案例。
- 现在基本不再使用：与其先训稠密模型再转换，不如一开始就直接训练目标 MoE。

## DeepSeek V1 → V2 → V3 的演进（含 MLA 与 MTP）[82:11 - 85:41]

- **DeepSeek MoE V1**：共享专家 + 细粒度专家 + 标准 top-k 路由 + 辅助均衡损失——现代 MoE 的原型。
- **V2**：规模放大（2 个共享专家、更多细粒度专家），并加入**设备级路由均衡**与**通信均衡**——这两项本质上是为系统效率而加的辅助损失。讲师借此强调：成功的 LM 训练不只是深度学习，还必须尊重系统约束。
- **V3**：仍是共享 + 细粒度专家，但均衡方式改变（aux-loss-free 的 bias 方案），专家加权改用 sigmoid + softmax，整体思路相近。
- **MLA（multi-head latent attention）**：不直接由隐藏状态产生 Q/K/V，而是先产生低维 latent $c$，再由 $c$ 生成 Q/K/V；KV cache 只需存 $c$，显著节省显存。复杂性在于与 RoPE 的兼容——需要用**非 latent 的维度**来编码位置。
- **MTP（multi-token prediction）**：一次预测多个未来 token，既有统计上的好处，也在系统上相当于内置了一个投机解码器（后续推理讲座会展开）。这个想法很巧妙，但尚未广泛流行。

## 要点回顾

- **长上下文的成本结构**：注意力随序列长度二次增长，长序列下取代 FFN 成为主导成本；FlashAttention 只改善常数因子，不改变复杂度。
- **线性注意力的起点**：去掉 softmax 后利用 $(QK^\top)V=Q(K^\top V)$，把二次依赖换成隐藏维度上的线性依赖；这一步有损，之后到 RNN 形式的等价是精确的。
- **RNN 对偶**：$S_t=S_{t-1}+k_tv_t^\top,\ y_t=q_t^\top S_t$ —— 训练用稠密矩阵乘并行，推理用固定大小的状态串行。
- **门控族谱**：Mamba-2 加输入依赖的衰减门 $\gamma_t$；Gated DeltaNet 再加“无输入”门 $\beta_t$ 与沿当前 key 方向的擦除投影 $(I-\beta_tk_tk_t^\top)$。只要门控只依赖输入，对偶性就保持。
- **混合是现实**：MiniMax M1（7:1）、Qwen 3.5（3:1 GDN）、Nemotron 3（Mamba-2 交替）都是混合架构；低混合比例几乎无损，比例过高长上下文性能明显退化；纯线性/纯 RNN 尚未在规模上被验证。
- **稀疏注意力（DSA）**：轻量索引器打分 + top-k 选 token，再在小集合上做全注意力；索引器仍二次但极轻（低精度/低维），且可在长上下文扩展阶段才接入。DeepSeek-V3.2 与 GLM 5 采用，性能损失很小。
- **MoE 的动机**：替换 FFN，参数量 ×N 而 FLOPs 不变；相同算力下更多稀疏参数普遍更好，并额外提供专家并行这一并行轴。
- **路由**：token choice top-k（内积路由）是共识；hash 路由可作基线，RL/bandit 与线性指派均未成为主流；DeepSeek 的细粒度 + 共享专家已成标准模板。
- **训练**：稀疏 → 门控不可微且看不到未选中专家；实际靠负载均衡辅助损失（Switch 的 $f_iP_i$ 形式、DeepSeek 的设备级均衡与 V3 的 bias 方案）解决专家坍缩；去掉均衡损失会导致几乎所有 token 涌向少数专家。
- **系统**：专家并行的 All-to-All 通信是主要代价，可用下投影降低传输量、用结构化稀疏矩阵乘提升硬件效率；早期丢 token 的随机性问题已被 dropless 框架解决。
- **稳定性与微调**：路由器 softmax 是新风险点（float32、z-loss）；MoE 微调易过拟合，常只调注意力或非 MoE 层，或用海量数据。
- **Upcycling**：复制稠密 MLP 成专家 + 随机路由继续训练，MiniCPM、Qwen-MoE 曾验证有效，现已不流行。
- **DeepSeek 谱系**：V1 确立原型 → V2 加入设备/通信均衡 → V3 采用 aux-loss-free 均衡与 sigmoid 加权；另有 MLA（latent 压缩 KV cache）与 MTP（多 token 预测，内置投机解码）。
