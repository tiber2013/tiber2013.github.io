# 第 12 讲 · 评估

> **Stanford CS336 语言模型从零构建 · L12** ｜ 讲者 Stanford Online ｜ 79 分钟 ｜ [原视频](https://www.youtube.com/watch?v=JpAxdTWQJxM)

## 核心结论

评估表面上只是“给模型发提示、算准确率”的机械流程，真正的难点在于把“我想要模型擅长对话/推理”这类抽象构念转化为具体、可信的指标。本讲按谱系梳理了六类评估：困惑度、考试题、开放式对话、智能体任务、纯推理与安全评估，并指出它们在难度、真实性与有效性之间存在取舍。困惑度仍广泛用于 scaling law，因为它是平滑可测的概率度量，但会把注意力平均分配到所有 token 上；考试类基准会被迅速刷爆，且无法反映真实使用；开放式回答只能靠成对比较加评分细则（rubric）才可靠；智能体评估实际评的是“模型 + scaffold”。在预训练数据不透明的时代，训练集污染无法根除，只能通过顺序异常检测、报告重叠、使用新数据或私有数据来缓解，并且必须人工审计样本质量。

## 为什么评估值得一整讲 [00:05 - 02:38]

课程此前已经覆盖了训练一个语言模型所需的全部环节：架构、优化器、训练主循环、用 kernel 与并行加速训练、scaling law，以及一部分推理加速。唯一剩下的部分是训练数据（下一周的主题）。而数据会塑造模型行为——用代码训练，模型擅长代码；只用 DNA 序列训练，它大概不会说英语。

但在谈数据之前，必须先明确“我们希望模型表现出什么行为”，这就是评估。

评估要回答的问题很简单：给定一个训练好的模型，它有多好？它看起来是机械流程：定义提示 → 发给模型 → 得到回答 → 算准确率。但它实际上是一个非常深、也非常重要的题目，因为**评估塑造了 AI 的发展方向**：它设定北极星，无论是开放还是闭源模型开发者，都把评估当作衡量进步的标尺。因此，谨慎设计评估，等于间接塑造模型的能力边界。

核心挑战在于：你从“我想让模型擅长对话或推理”这样的**抽象构念**出发，而评估就是把抽象构念转化为**由具体提示或环境支撑的具体指标**的过程。整讲会反复出现这一转化。

## 「好」的不同定义 [02:38 - 05:16]

在具体指标之前，讲师先列举了几种关于“好”的直觉，并强调没有哪一种必然正确：

- **跑分高**：Artificial Analysis 的 intelligence index 已成为衡量模型“智能”的准标准，它聚合了包括 GDPval、Terminal-Bench Hard、Humanity's Last Exam、GPQA Diamond 等在内的十项评测。
- **跑分高且便宜**：把智能指数对推理成本（对数坐标）作图，二者正相关但并不完全对齐——存在“高智能、低成本”的更优象限。
- **人类更喜欢**：Arena AI（原 Chatbot Arena）基于人类偏好给出排名。
- **有人愿意付费使用**：OpenRouter 汇总各模型的 token 使用量，提供一种经济学视角——不确定什么是好，但有人付钱说明它不差（不过这不代表全部模型使用情况）。

## 困惑度：最自然的评估 [05:16 - 10:00]

语言模型的本质是 token 序列上的概率分布 $p(x)$。在这个视角下，评估分布最自然的方式就是困惑度（perplexity），它与似然、log loss 是同一族概念：

$$\text{PPL}(D) = \left(\frac{1}{p(D)}\right)^{1/|D|}$$

即“模型给测试集 $D$ 分配了多少概率质量”，再取归一化使数值更易读。预训练时我们最小化训练集上的困惑度，那么最直接的做法就是测测试集上的困惑度。

**经典的分布内（in-distribution）范式**：在数据集的 train split 上训练，在 test split 上测困惑度。2010 年代的语言建模论文基本都这么做，标准数据集包括 Penn Treebank（WSJ）、WikiText-103（维基百科）以及取自机器翻译语料（EuroParl、UN、新闻）的 One Billion Word Benchmark。Jozefowicz 等人 2016 年的工作用纯 CNN+LSTM 把 One Billion Word 上的困惑度从 51.3 降到 30.0，这是“纯神经网络明显更优”的首个决定性结果。

**GPT-2（2019）改变了范式**：它在 WebText（40GB，来自 Reddit 外链网页）上训练，却在大家通用的标准数据集上做**零样本、分布外**评估。结果显示，在小数据集上迁移收益明显（PTB 困惑度 35，优于当时 SOTA 的 46），但在有充足分布内数据的较大数据集（如 1BW）上不如 SOTA。讲师提醒：不确定当时是否做了严格的去污染，因为训练数据与这些数据集可能有重叠。无论如何，这开启了“在大规模数据上训练、在标准基准上评估”的新范式。

## 困惑度的信念与局限 [10:00 - 17:10]

### “困惑度就是一切”（更多是信念而非科学）

设真实分布为 $t$、模型为 $p$。可能达到的最好困惑度是真实分布的熵 $H(t)$，且当且仅当 $p=t$ 时取到。而如果 $p=t$，原则上所有任务都能解：只要条件在问题上就能生成解、条件在问题上就能生成答案 $p(\text{solution}\mid\text{problem})$。于是推论是：不断压低困惑度，最终就会“抵达 AGI”。

讲师坦言这套论证听起来有点玄，但它确实是许多人（尤其在 GPT-3 之前收益尚不明显时）持续放大模型规模的强大驱动力。

### “困惑度也许超出了你需要的”

以 “Stanford was founded in 1885” 为例：困惑度会惩罚所有 token 的预测，其中 “1885” 承载了世界知识、是有意义的问答信号，而句首词甚至 “founded” 未必那么重要——但困惑度一视同仁，对每一处偏离真实分布都收取 bits。

解决方案是测**条件困惑度**：先给定提示，只测回答部分的

$$p(\text{response}\mid\text{prompt})^{1/|\text{response}|}$$

这样就可以聚焦在你关心的 token 上，忽略附带的部分。

### 有些基准其实是“伪装的困惑度”

- **LAMBADA（Paperno 等，2016）**：完形填空式的闭式任务。给一段长上下文，再给一个含空格的句子（如 “Do you honestly think that I would want you to have a \_\_\_\_\_?”），要求填出目标词。虽然按准确率计分，本质仍是下一 token 预测；关键在于这些空位是精心挑选的，必须依赖长距离上下文才能解出。早期 GPT 系列论文特别看重它，因为它们关心长上下文建模，认为这是解锁推理能力的关键。
- **HellaSwag**：多选句子的补全（如 “A woman is outside with a pug and a dog. The dog is running around, she \_\_\_\_.”），某种意义上是“伪装成多选的困惑度”。

### 如果你要做困惑度排行榜，先等一下

困惑度榜单要求提交方返回 log probability，但评测方无法轻易验证这些概率是否构成合法分布（是否归一化到 1）——理论上一个永远返回 log prob 0 的“模型”就能拿到极好的分数。要检查只能看代码，存在信任问题；对 VAE 这类只能算出概率下界的模型，还要额外信任其数学正确性。

相比之下，下游任务评估可以直接黑箱：给提示、取回答、算准确率，无需暴露分布。因此困惑度评估在机制上根本不同，需要格外小心。

## 考试类基准：MMLU、GPQA、HLE [18:13 - 31:50]

考试是对人类的能力检验，同样可以搬到模型上。其优点很明确：可以精确控制学科与难度、可以设计成答案唯一从而易于判分。因此 LM 基准文化长期建立在“考试”这一隐喻上。

### MMLU（Hendrycks 等，2020）

覆盖 57 个学科（数学、美国历史、法律、道德等），全部为多选。当时（GPT-3 前后）人们还不认为语言模型是通用任务求解器，因此这是一个“提前布局”的项目：由学生团队在互联网上搜集整理资料，构建出相当全面的数据集。尽管名字里有“language understanding”，它实际测的更多是**知识与推理**。

评估方式是 GPT-3 上的少样本提示：写成“以下是一些高中数学问题”＋若干问答示例＋最后一个待答问题，让模型给出答案。今天看很平常，但在当时用这种复杂提示加示例去期待模型做出合理回答，是相当激进的做法。结果小模型近乎随机，GPT-3 明显高于随机。此后该基准逐步被刷爆，如今已在 90 分上下。

### MMLU-Pro（Wang 等，2024）

针对 MMLU 饱和的改进：去除噪声题与平凡题、把 4 个选项扩到 10 个、改用 chain of thought 评估（给模型更多推理机会）。刚发布时模型准确率回落到 33%，但如今又回升到接近 90。

### GPQA（Rein 等，2023）

“Google Proof QA”的动机：如果一个问题能靠搜索解决，而模型又是在互联网上训练的，那它大概太简单。因此需要真正困难、达到博士水平的问题，而这必须投入大量人力。做法是 61 位来自 Upwork 的博士合同工出题，随后经过多轮专家校验与修订，再交由非专家（在其他领域是专家、允许使用 Google、约 15 分钟到平均 37 分钟）作答验证。

**diamond 子集**的判定标准：2 位专家一致同意答案，且 3 位非专家中最多 1 位答对。博士专家准确率仅 65%，非专家（30 分钟 + Google）34%，GPT-4 当时 39%——如今该基准已达 94。

### Humanity's Last Exam（HLE，Phan 等，2025）

“模型太强了，那就尽力造一个最难的。”特点：2500 题、多模态、多学科、多选加短答；通过奖金与署名激励众包出题，经多阶段评审并用前沿模型过滤，另外保留一份不公开的私有集以防进入训练（当然 API 调用本身是否会被记录只能“但愿不会”）。这类数据集论文的典型构图是：“已有基准上模型都很强，我的数据集上模型都很差”——HLE 上模型当时只有个位数。到 2026 年最高分也只有 64.7，仍留有空间。

### 关于污染的提问

有同学问：怎么知道这些题没进训练集？讲师回答：**我们不知道**，因为不知道训练集里有什么；而且污染往往是间接的——不是直接训练在测试集上，而是训练了这些题目的来源材料。所以看到这类分数应始终持保留态度。HLE 保留私有集、只通过 API 调用，是目前的一种应对方式。

### 为什么多选还活着

多选常被批评“太简单”，但难度不是问题——多选也可以出得极难。真正的限制在于**多选限定了可问问题的集合**。考试类基准最大的问题另有其他：**它不反映真实使用**。除了评估时，没人会给模型出 HLE 题；真实场景多是开放式的，甚至没有正确答案、问题本身也不规范。

关于准确率如何计算：多选就是看模型输出的字母与标准答案是否一致；模型可能直接采样出字母，也可能先生成思维链再抽取答案，**抽取方式对评估结果很敏感**（讲师表示这属于另一个话题，本讲不展开）。

## 开放式对话评估：Arena、AlpacaEval、WildBench [31:52 - 44:58]

真实提问是开放式的，例如“我想做甜菜沙拉，哪些香草合适、哪些不合适”，回答也开放，既无标准答案也无法精确匹配。有三条思路。

### 1. Chatbot Arena：人类两两投票 + Elo

网站对任何互联网用户免费开放聊天，但每次返回**两个匿名模型的两份回答**，由用户选择“A 更好 / 都好 / 都差 / B 更好”。由此积累成对比较数据，再用 Elo 拟合评分。

Elo 模型把 A 战胜 B 的概率写成两人分差的函数：

$$P(A \text{ beats } B) = f(r_A - r_B)$$

$r_A$ 越高，A 获胜概率越大；以各模型 Elo 分为参数，最大化已观测成对比较的似然即可拟合出评分。

优点：

- 提示来自真实用户；免费使用形成了“用户想真的做点事”的隐性激励。
- 不需要把同一批提示喂给所有模型——Elo 的精髓正在于此：只要比较图连通，稀疏采样也能推出排名，这对人类评分尤其关键（不能指望人评完所有模型）。
- 新提示、新模型可以自然地被增量纳入。

隐忧：

- “互联网上的随机人”是什么分布并不清楚，人口统计学信息也说明不了全部。
- 可能存在偏差、刷票者，甚至提交模型的人来给自己刷分，环境像“西部荒野”。
- 二元偏好把**风格与正确性混在一起**：国际象棋里 Elo 很合理，因为只有输赢；但“哪个回答更好”远没有那么清晰。
- 由提问者当裁判有好的一面（他有意图，能判断意图是否被满足），但他提问往往正因为不知道答案，凭什么判断谁对？
- 谄媚（sycophancy）：讨喜的回答可能压过正确但诚实的回答。

### 2. AlpacaEval：LLM 当裁判

用一批来自不同来源的指令，指标是**相对基线模型的胜率**：让待评模型与基线模型（当时是 GPT-4 preview）各生成一个回答，再由裁判模型（同样是 GPT-4 preview）判断哪个更好。这就是今天非常流行的 **LLM-as-a-judge**，其固有偏差可通过多裁判集成等方式缓解。

早期的一个明显问题：**LLM 裁判偏爱长回答**，导致一批微调模型仅靠把回答写长就刷出很高的 AlpacaEval 分数；后续工作用简单的回归方法对该指标做去偏。

这引出一个更一般的问题：**怎么评估一个指标本身好不好？** 没有标准答案，一种做法是看它与其他指标的相关性。AlpacaEval 与 Chatbot Arena 的相关性高达 0.98，因此如果你不想上人类竞技场、也不想等人类投票，可以用它作代理。但要注意：这个相关性只是在**特定模型集合**上测得的，对强于 GPT-4 preview 的模型未必成立。

### 3. WildBench：真实对话 + 任务专属清单

提示来自人类与聊天机器人的真实对话（同样提供免费服务来收集），评估同样用 LLM 裁判。主要创新是引入**针对具体提示/任务生成的 checklist（评分细则）**：直接问裁判“这个回答好不好”本身是定义不清的任务，而有了清单或 rubric，评估任务就被大幅收窄、变得良定义。它同样报告了与 Chatbot Arena 的相关性——讲师也承认这里有一点循环论证的意味（凭什么说 Arena 就是金标准）。

### 小结

开放式回答没有明确解法，但有几条经验：

- **成对比较**通常优于绝对打分：对两个相近的回答，成对比较能给出“这个稍好”的方向性信息；而“7 分还是 8 分”的信号很弱。
- 时刻警惕人类裁判与 LLM 裁判各自的偏差。
- 多裁判（人类 + 模型）一致认为你的模型更好，才比较可信。
- 开放式评估本身并不良定义，**rubric / checklist 是提高可靠性的关键**——这与人类众包的经验一致：不给细则就让人打分，通常只能得到无意义的结果。

## 智能体评估：SWE-bench、Terminal-Bench、CTF、MLE [45:03 - 53:51]

前面评估的是“模型会说什么”（聊天），现在评估“模型会做什么”（智能体）。**智能体 = 语言模型 + scaffold**，scaffold 决定模型如何被调用、能访问哪些工具等。

- **SWE-bench（及其 Verified 版）**：输入是一个代码库加一条 GitHub issue 描述，任务是提交 PR；判定方式直接看单元测试——有些测试在修复前不通过，修复后必须通过，且不能弄坏其他测试。判分非常干净利落。2024 年时约 16%，如今已到 93%。它开创了“在真实环境中评估写代码能力”的思路。
- **Terminal-Bench**：更通用，环境就是一个计算机终端，任务是若干可通过敲命令完成的作业。环境简单且普适；任务由全球 93 位贡献者众包，其中 89 个任务构成 Terminal-Bench 2.0；难度跨度从 1 小时到一周以上（取决于专家还是新手）。榜单上的另一看点是：**同一个模型配不同 agent，准确率不同**。
- **网络安全 CTF**：40 个 capture-the-flag 任务。智能体获得一个环境，可以运行命令、查看源码、访问 Web 服务器，目标是攻入服务器取出唯一字符串（flag）。示例 scaffold 很简陋：单一连续记忆，产生动作 → 获得环境反馈 → 拼进缓冲区。这种历史会迅速膨胀，需要更好的上下文管理。发布时最强模型约 10%，现在已被完全解决。
- **MLE 工程**：一批 Kaggle 竞赛，智能体需要读取数据集与描述、写代码、训模型、提交并得分。榜上语言模型仍是“常客”，但不同 agent scaffold 之间差异明显。

**scaffold 极为重要**：显式规划（维护待办清单并逐项勾掉，而不是纯 chain-of-thought 随波逐流导致丢失全局）、层级委派（主 agent 把清理过的上下文交给子 agent，只收回结果而不看全部细节，实现封装）、显式读写文件做记忆（上下文窗口装不下）、“上下文工程”式的过程管理（何时委派、何时换策略、什么写入持久记忆），且这些通常针对特定模型调优。

因此，评估智能体实际上是在同时评估语言模型与 agent scaffold，这比单纯的“语言模型评估”范围更宽。

## 纯推理：ARC-AGI [53:56 - 60:10]

前面所有任务都需要语言与世界知识。能否把**推理 / 流体智能**从知识中剥离出来？若可以，那会是更“纯”的智能度量。

ARC-AGI 于 2019 年启动，目标正是如此：每个任务都设计成人类 100% 可解但 AI 很难，且每道题都是“独特的雪花”，背事实、记旧题都不该有帮助。示例第一版题目是给几组图案，猜下一个图案（大致规律是把黄色填满形成矩形）。

时间线很能说明问题：

- ARC-AGI 1 发布时，预训练模型约等于 0——正如作者所愿，预训练学到的互联网事实与语言模式对此几乎无用。
- 2024 年推理模型（o1 / o3 一类）出现后，分数陡然起飞，如今 ARC-AGI 1 基本被解决。
- 2025 年的 ARC-AGI 2 尚未解决，但看起来正在被攻克。
- 最新（讲课时“上个月”）的 ARC-AGI 3 变成**交互式环境**，不含语言，只能靠模式摸索，目前分数极低。

需要注意的局限：把推理与知识完全解耦非常困难，这大概是最好的尝试，但未必能真正分离（而且只要有人在意，任何基准都可以被针对性设计）；此外它被约束在**人类可解**范围内，无法覆盖超人推理，例如拿 IMO 金牌或解决开放数学问题。不过它确实暴露了当前模型的缺口。

关于输入形式：题目是（约 64×64 的）图形，可以给图像，也可以给 ASCII art 或文本表示；但无论如何都存在模型必须处理的**空间要素**，那不是英语或自然语言。

## 安全评估 [60:12 - 65:09]

汽车的安全是明确的：撞墙测试、气囊、假人，背后是数十年游说与标准制定。AI 的安全则没有这么好的答案。

- **HarmBench**：给模型喂有害提示，期望它拒答。这是人们想到“安全”时最主要的图景——阻止恶意行为者利用模型。
- **Airbench**：尝试更整体地看安全，梳理欧盟、中国、美国的监管框架与公司政策，建立“所有可能出错之事”的分类法，再据此构造提示并评估。
- **越狱（jailbreak）**：模型被训练成拒绝有害指令，但只要够聪明就能绕过。早期工作用自动优化（如 GCG 这类逐坐标优化）搜索提示；值得注意的是，**在开源模型上优化的对抗提示可以迁移到闭源模型**，于是“一段乱码 + 毁灭人类的分步计划”就能让当时的模型照做。讲师希望这类攻击今天已经失效，但期望行为显然应该是拒答。

安全之所以难，在于它高度依赖语境：涉及政治、法律、社会规范，且各国不同。风险也种类繁多、需要不同程度的关注：幻觉（在医疗、法律、金融场景尤甚，但与能力正相关）、谄媚、协助犯罪（可能与能力方向相反）、不平等、批判性思维的丧失（同样与能力相关）。若把安全理解为“确保 AI 对人类是好的”，这是一个远比本节课能覆盖的更复杂的议题。此外还有**两用性**：网络安全智能体既能入侵系统，也能做渗透测试加固系统，很难简单判定是风险还是收益。

## 评估的整体考量：现实性、污染、数据质量 [65:14 - 75:41]

### 现实性 / 生态效度

评估在多大程度上反映真实使用？考试离真实使用很远；Arena 来自真人，但人群与用例分布是否合适存疑。几个面向“用例级”而非“单条 query 级”现实的努力：

- **GDPval（OpenAI）**：按美国 GDP 选取前九大行业，请平均约 14 年经验的专业人士（护士、礼宾、房产经纪、影视剪辑等）出任务。
- **医疗领域**：此前医疗基准多基于标准化考试，但人类医生也不是考完试就上手术台；该项目由 29 位临床医生提供 121 个任务，代表临床医生真正会问模型的那类问题，与多选题考试差别很大。
- **真实使用数据**：真正掌握“人们在用它做什么”数据的是模型开发者。出于隐私，不能直接查看用户数据，但可以让语言模型去分析真实数据并总结模式（例如人们用 Claude 做什么）。这里存在**现实性与隐私的张力**：最理想的是从真实 query 流中采样，以深入理解错误类型，但这会触碰隐私。

### 科学性有效性：训练/测试重叠

机器学习入门第一课是“不要在测试集上训练”，在 foundation model 之前这很清晰：ImageNet、SQuAD 等都有 train/test split，大家玩同一个游戏。如今模型在互联网上训练、且你不知道数据里有什么，情况完全不同。四条应对路线：

1. **推断模型是否见过测试数据**：基准中题目的顺序本应是随机的；如果模型偏好某种与基准原顺序一致的特定排列，那它很可能训练过该基准（转写提到这来自 Tatsuo 组的工作）。
2. **推动报告训练/测试重叠**：这是一种规范问题——就像统计学里总该报告置信区间，模型提供方若要声称某个 GPQA 分数，就应给出“未在测试集上训练”的论证（一篇 position paper 的主张）。
3. **干脆假设最坏情况，用新数据造评估**：如 Code Bench、Untreated Eval 一类工作，抓取新网页、新 arXiv 论文或 GitHub 内容，构造晚于模型截止日期的评估。看起来很稳健，但**时间戳也不总是安全**：GitHub 上的东西可能是从别的仓库派生来的，未必真的“新鲜”。
4. **私有评估**：Google、OpenAI 这类公司可用不在互联网上的内部代码库；个人可以用自己未公开的写作（例如讲师研究生阶段被拒、从未上网的论文）。这条路相当可靠，而且**对困惑度评估尤其友好**——只需要一份好数据集和 log probability。

### 数据集质量

SWE-bench 之所以有 Verified 版，是因为原版的单元测试不够严格等问题被修掉了；GSM8K、MMLU 等也经历过更仔细的审计，发现“这道题其实缺了曲线，无法作答”“婴儿穿没穿袜子根本无从判断”之类的坏样本。

智能体基准更难审计，因为它不是“看题面和选项”就能判断，而是一整个环境：

- 测试用例可能不完整——通过所有测试并不等于方案真的可用。
- 有工作指出，智能体只要输出**空回答**就能在某基准上拿到约 38%，这类平凡性必须警惕。

工具层面，**Docent** 用语言模型检查智能体的执行轨迹以发现问题，算是对“重度定量化基准”的定性补充。讲师的一般建议是：无论你是开发基准还是跑基准，**都要亲眼看输出、做审计**，确认你测的确实是你以为在测的东西。

## 评估的目的与「评估什么」 [75:41 - 78:34]

没有一种评估能统御一切。做评估时必须明确目的，而这一点常常没被讲清楚：

- 用户或企业要做**采购决策**：某个用例该选 A 还是 B。
- 研究者想测量自己心中那个**直觉的“智能”**概念。
- 出于商业或政策原因，想理解**收益与危害**。
- 模型开发者想要**反馈以改进模型**。

不同目标会导向不同的基准或组合策略。

另一个常被忽略的问题是**我们在评估什么**。foundation model 之前，研究者评估的是**方法**：有固定的 train/test split，唯一变化的是算法。今天主要评估**模型与系统**，几乎什么都可以变。也有例外：nanoGPT speedrun 就是刻意用来评估算法的（训练能有多快）。但绝大多数语言模型评估评的是最终交付、会被人真正使用的那个模型——这本身是合理的，关键在于**有意识地声明自己的目标与规则**（评方法、评模型，还是评智能体）。

## 要点回顾

- 评估的本质是把抽象构念（“擅长对话/推理”）转化为由具体提示或环境支撑的具体指标；它决定整个领域的发展方向。
- “好”没有唯一定义：跑分、性价比、人类偏好、付费使用都只是视角，没有哪个必然正确。
- 困惑度 $\left(1/p(D)\right)^{1/|D|}$ 是最自然的评估，2010 年代以 Penn Treebank、WikiText-103、1BW 做分布内评测；GPT-2 转向“大规模训练 + 零样本分布外评测”。
- “困惑度就是一切”的论证：最好困惑度是真实分布的熵 $H(t)$，当且仅当 $p=t$ 时取到，而 $p=t$ 意味着所有任务可解——这更多是信念，却是推动 scaling 的真实动力。
- 困惑度的局限：它平均惩罚所有 token，可用**条件困惑度**聚焦关键片段；LAMBADA、HellaSwag 本质上是“伪装的困惑度”。
- 困惑度榜单需要信任提交方返回合法分布；下游任务则可直接黑箱算准确率。
- 考试类基准（MMLU → MMLU-Pro → GPQA → HLE）通过加学科、加选项、加难度、请博士出题不断自我更新，但会迅速饱和，且**不反映真实使用**；污染无法排除，且常常是间接的。
- 开放式评估：Chatbot Arena 用匿名两两投票 + Elo（$P(A\text{ beats }B)=f(r_A-r_B)$）；AlpacaEval 用 LLM 裁判算对基线的胜率（需防长回答偏好）；WildBench 用任务专属 checklist 让评判良定义。成对比较优于绝对打分，rubric 是可靠性的关键。
- 智能体评估评的是“模型 + scaffold”：SWE-bench（单元测试判分）、Terminal-Bench（终端环境）、CTF（夺旗）、MLE（Kaggle 竞赛）；显式规划、层级委派、文件式记忆与上下文工程都很关键，同一模型换 scaffold 分数不同。
- ARC-AGI 试图把推理从知识中剥离：预训练模型近乎为零，2024 年推理模型之后被快速攻克；但它受限于“人类可解”，且完全解耦未必可能。
- 安全评估（HarmBench 的拒答、Airbench 的监管分类法、GCG 越狱与跨模型迁移）高度依赖语境，风险种类繁多且与能力的关系方向不一，还有两用之困。
- 有效性考量：现实性（GDPval、临床任务、真实使用分析，后者与隐私冲突）、训练/测试重叠（顺序异常检测、报告重叠、构造新数据、私有评估）、数据集质量（基准要审计，智能体基准尤其难，空回答也能拿分）。
- 结论：没有唯一正确的评估，先明确你在测什么、为谁而测；难度、现实性、有效性、无污染往往不可兼得，必须按目标选择妥协。
